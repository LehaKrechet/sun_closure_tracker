# Система мониторинга облачности и управления двигателем

Данный проект представляет собой распределенную систему компьютерного зрения, предназначенную для автоматического управления двигателем в зависимости от наличия облаков, перекрывающих солнце.

## 🏗 Архитектура системы

Система разделена на два независимых компонента:

1. **Client (Vision System):**
* Запускается на устройстве с камерой (или ПК с видеопотоком).
* Использует **OpenCV** для захвата изображения.
* Применяет **Фильтр Калмана** для трекинга облаков и предсказания их траектории.
* Отправляет HTTP-запросы на сервер управления при обнаружении угрозы перекрытия солнца.


2. **Server (Hardware Controller):**
* Запускается на конечном устройстве (например, Raspberry Pi / ARM-плата).
* Реализует HTTP-сервер для обработки команд.
* Использует **Конечный автомат (FSM)** для безопасного управления состоянием двигателя (защита от дубликатов команд).
* Управляет физическим оборудованием через прямое взаимодействие с **GPIO (ioctl)**.



## 📂 Структура проекта

* `app.cpp` / `App.h`: Основная логика работы клиента.
* `recognizer.cpp` / `Recognizer.h`: Ядро обработки изображений и предиктивной аналитики.
* `server.cpp`: Серверная часть, принимающая команды по сети.
* `gpio_control.c`: Низкоуровневый драйвер управления пинами GPIO.
* `Sendler.cpp`: HTTP-клиент для передачи команд на сервер.

## 🚀 Сборка и установка

### Требования

* C++17 или выше.
* Библиотеки: `OpenCV`, `httplib`, `nlohmann/json`.

### Сборка Клиента (Vision)

Настройте CMake или используйте ваш стандартный процесс сборки, подключив `OpenCV` и `httplib`.

На Ubuntu
```bash
mkdir build
cd build
cmake ..
make

```

### Сборка Сервера (ARM Target)

Для кросс-компиляции под целевое устройство (ARM):

```bash
arm-linux-gnueabi-g++ \
  -static \
  -pthread \
  -o arm_server \
  src/server.cpp \
  src/gpio_control.c \
  -I./library -I./include

```

Для проверки работоспособности на ПК (через QEMU):

```bash
qemu-arm-static ./arm_server

```

## ⚙️ Принцип работы

1. **Детекция:** Клиент захватывает кадры, переводит их в HSV, накладывает маску на яркие области (облака).
2. **Трекинг:** Облака отслеживаются с помощью Kalman Filter. Вычисляется вектор скорости и время до пересечения с позицией солнца.
3. **Команда:** При прогнозе перекрытия `t < 3 сек` отправляется POST-запрос `{"command": "start"}`. При открытии — `{"command": "stop"}`.
4. **Исполнение:** Сервер получает команду, проверяет текущее состояние через `EngineStateMachine` и физически переключает состояние GPIO.

## 📝 Разработчикам

* **Логика FSM:** Сервер не выполняет команду `start`, если мотор уже работает. Это предотвращает аппаратные конфликты.
* **GPIO:** Обратите внимание, что `gpio_control` использует `ioctl` с `GPIOHANDLE_REQUEST_OUTPUT`. Убедитесь, что пользователь имеет права доступа к `/dev/gpiochip*`.
